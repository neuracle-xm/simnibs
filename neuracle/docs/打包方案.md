## 打包方案

### 1. 本轮目标

本轮实现聚焦以下闭环：

1. `head_model.py`、`ti_forward.py`、`ti_inverse.py` 支持终端直接执行和传参
2. 最终打包目录名为 `simnibs_package`
3. `neuracle` 直接出现在 `simnibs_package/neuracle`
4. `simnibs_env` 只负责解释器和第三方依赖
5. 不再把 `neuracle` 作为 `site-package` 分发
6. 不打包 `documentation`
7. 裁掉 `docs`、`demo`、`validation`、`private_gitignore`、`atlas/atlas`
8. 裁掉 `atlas` 中仅供离线处理使用的脚本

### 2. 实现策略

#### 2.1 CLI 改造

三个脚本统一补齐：

1. `if __name__ == "__main__":`
2. `argparse` 参数解析
3. 参数校验
4. 统一退出码

#### 2.2 根目录分发

打包产物结构固定为：

```text
simnibs_package/
├─ neuracle/
└─ simnibs_env/
```

`packing/pack.py` 负责：

1. 解包 `conda_pack` 产物到 `simnibs_env`
2. 删除 `simnibs_env/Lib/site-packages/neuracle`
3. 将裁剪后的 `neuracle` 复制到 `simnibs_package/neuracle`

#### 2.3 运行路径模型

开发态和安装态统一要求：

1. `NEURACLE_DIR = 当前 neuracle 目录`
2. `PACKAGE_ROOT = NEURACLE_DIR.parent`
3. `PROJECT_ROOT = PACKAGE_ROOT`
4. `DATA_ROOT = PACKAGE_ROOT/data`
5. `LOG_ROOT = PACKAGE_ROOT/log`

#### 2.4 资源裁剪

保留：

1. Python 源码
2. `charm_override.json`
3. `atlas/manifests`
4. `atlas/standardized`

排除：

1. `documentation`
2. `neuracle/docs`
3. `neuracle/private_gitignore`
4. `neuracle/**/demo`
5. `neuracle/**/validation`
6. `neuracle/atlas/atlas`
7. `neuracle/atlas/build_standardized_registry.py`
8. `neuracle/atlas/generate_standardized_rois.py`
9. `neuracle/atlas/standardize_atlases.py`
10. `neuracle/atlas/validate_standardized_atlases.py`
11. `neuracle/atlas/structure.md`

### 3. 验证方式

需要验证：

1. `simnibs_package/simnibs_env/python.exe simnibs_package/neuracle/head_model.py --help`
2. `simnibs_package/simnibs_env/python.exe simnibs_package/neuracle/ti_forward.py --help`
3. `simnibs_package/simnibs_env/python.exe simnibs_package/neuracle/ti_inverse.py --help`
4. 使用伪参数运行 `ti_forward.py` 和 `ti_inverse.py`，确认数据路径指向 `simnibs_package/data`

### 4. 说明

这套方案的重点不是让用户在安装态直接 `import neuracle`。
当前支持的标准用法是：

```text
simnibs_package/simnibs_env/python.exe simnibs_package/neuracle/*.py ...
```

### 5. 当前打包方式

当前 `packing/pack.py` 的推荐入口已经收敛为一种标准用法：

```powershell
python packing/pack.py --env simnibs_env
```

该命令面向开发环境中的 `simnibs_env`，默认假设仓库内的 `simnibs` 可能是 editable 安装。

执行流程如下：

1. 自动克隆 `simnibs_env` 到临时环境
2. 自动清空 `dist/` 目录
3. 自动通过 `python setup.py bdist_wheel --dist-dir dist` 重新构建当前版本对应的 `simnibs-*.whl`
4. 在临时环境中卸载 editable 安装的 `simnibs`
5. 在临时环境中安装 wheel 版本的 `simnibs`
6. 使用该临时环境执行 `conda-pack`
7. 解包到 `simnibs_package/simnibs_env`
8. 复制裁剪后的 `neuracle` 到 `simnibs_package/neuracle`
9. 打包完成后自动删除临时环境

这样做的目的有两点：

1. 避免 `conda-pack` 因 editable package 报错
2. 避免污染日常开发使用的 `simnibs_env`

补充说明：

1. `--env` 传入的仍然是已有 conda 环境名
2. wheel 不需要手动传参，脚本会在打包前自动重新构建
3. 若 wheel 构建失败，则打包会直接失败
4. wheel 构建阶段使用 `setup.py bdist_wheel`，不依赖 `python -m build`

### 6. 版本号策略

当前版本号策略已经改成：**直接使用 git tag**。

也就是说：

1. 不再因为当前分支名是 `dev` 而自动把版本从 `4.6.0` 推成 `4.7.0`
2. `setuptools_scm` 解析出来的版本会直接等于最新 tag
3. 在当前仓库里，若最新 tag 是 `v4.6.0`，则新构建产物的目标版本就是 `4.6.0`

这一策略同时影响：

1. `setup.py` 构建 wheel 时的版本号
2. `packing/pack.py` 打包时读取到的版本号
